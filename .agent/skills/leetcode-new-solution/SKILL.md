# LeetCode 新解法 Skill

## 触发时机
用户在已完成解答的题目中要求：
- "新开解答"
- "添加另一种解法"
- "用XX方法再解一次"
- "我想试试另一种思路"

## 工作流程

### 1. 检查现有解答文件
查看题目目录下是否存在 `[题号].ts` 文件：
```bash
ls "src/[题号].*/[题号].ts"
```

### 2. 重命名原解答
如果存在 `[题号].ts`，将其重命名为 `[题号].1.ts`（第一个解法）：
```bash
mv "src/[题号].[题目名称]/[题号].ts" "src/[题号].[题目名称]/[题号].1.ts"
```

**序号规则**：
- 如果已有 `[题号].1.ts`、`[题号].2.ts`，则新文件命名为 `[题号].3.ts`
- 自动检测最大序号，新文件序号 = 最大序号 + 1

### 3. 创建新的解答模板
创建新的 `[题号].ts` 文件，保留题目描述和函数签名：

```typescript
/**
 * [题号]. [题目名称]
 * https://leetcode.cn/problems/[英文slug]/
 *
 * [题目描述和示例]
 */

function [函数名](参数): 返回类型 {
    // TODO: 实现你的算法（新解法）
    return 默认值;
}

export default [函数名];
```

**注意**：
- 从原解答文件中复制题目描述注释
- 清空函数体
- **不在解答文件中添加解法索引**（解法索引统一放在 README.md 中）

### 4. 更新测试文件引用（如果需要）
检查测试文件是否直接导入 `[题号].ts`：
```typescript
import [函数名] from './[题号]'
```

**通常不需要修改测试文件**，因为测试文件仍然导入 `[题号].ts`（新的解答）。

### 5. 提示用户
告知用户：
- 原解答已保存为 `[题号].1.ts`
- 新解答模板已创建在 `[题号].ts`
- 可以开始编写新解法
- 完成解答后使用"总结第X题"命令，会在 README 中更新解法索引

### 6. Git 操作
```bash
git add "src/[题号].*/"
```

**只 add，不 commit/push**

## 示例

### 场景：用户说"我想用动态规划再解一次第53题"

执行步骤：
1. 检查 `src/53. 最大子数组和/53.ts` 存在
2. 重命名：`53.ts` → `53.1.ts`
3. 创建新的 `53.ts`（空白模板）
4. git add

结果：
```
src/53. 最大子数组和/
├── 53.1.ts      # 原解答（贪心/前缀和）
├── 53.ts        # 新解答模板（待实现动态规划）
└── 53.test.ts   # 测试文件（不变）
```

## 注意事项
1. **不要修改测试文件**：测试文件始终导入 `[题号].ts`
2. **保留题目注释**：新解答文件应包含完整的题目描述
3. **序号递增**：自动检测已有解法数量，新文件序号正确递增
4. **不覆盖原解答**：确保原解答被正确重命名保存
5. **解法索引在 README**：不在解答文件中添加解法索引，统一由总结时在 README 中维护
6. **总结时更新对应关系**：当用户后续要求"总结第X题"时，需要在 README.md 中记录多种解法的对应关系
