# LeetCode 题解总结 Skill

## 触发时机
用户要求"总结第 X 题"或"对第 X 题进行总结"时，表示该题已解答完成。

## 工作流程

### 1. 在解答文件中添加精简总结和点评
检查题目目录下的解答文件（`[题号].ts` 或 `[题号].1.ts`、`[题号].2.ts` 等）。

**对于当前解答文件**（`[题号].ts`），在**函数上方**添加精简注释：

```typescript
/**
 * 解法：[方法名称，如"滑动窗口"、"动态规划"]
 * 思路：[一句话概括核心思路，不超过30字]
 * 评价：[高手视角评价，见下方规范]
 */
```

**评价规范**（以算法竞赛顶级选手视角）：
- **是否推荐**：明确标注 ✅推荐 / ⚠️可选 / ❌不推荐
- **核心优缺点**：指出1-2个关键优势或致命缺陷
- **适用场景**：什么情况下该解法最优
- **关注思路**：评价算法思想，不评价编码风格
- **精简犀利**：50字以内，直击要害

**示例**：
```typescript
/**
 * 解法：二分查找 + 前缀和
 * 思路：前缀和转化问题，二分查找满足条件的最短子数组
 * 评价：✅推荐。标准解法，时间O(nlogn)可接受。单调队列O(n)更优但实现复杂，面试此解法足够。
 */
```

**注意**：
- **只在当前解答文件**（`[题号].ts`）中添加总结和点评
- **不在解答文件中添加解法索引**（解法索引统一放在 README.md 中）
- 如果用户之前已经为其他解法文件（如 `54.1.ts`）添加过总结，不要覆盖

### 2. 创建/更新题目 README
查看题目目录结构，创建或更新 `README.md`：

```markdown
# 题后总结

## 知识点
[算法标签]

## 思路
[解题步骤]

## 核心逻辑
[关键代码]

## 关键点
[实现要点]

## 易错点
[注意事项]

## 复杂度
- 时间：O(?)
- 空间：O(?)

## 示例演示
[执行过程表格]

## 多种解法（如有）

### 解法索引
本目录包含以下解法文件：
- `[题号].1.ts`: [解法一名称]
- `[题号].2.ts`: [解法二名称]
- `[题号].ts`: [当前解法名称]

**注意**：各解法的详细思路和点评请查看对应文件顶部的注释。

## 算法对比
[对比表格]
```

**多解法时的处理**：
- **解法索引只列文件名和方法名**，不重复展示思路和评价
- 详细的解法思路和点评已在各解答文件顶部注释中
- README 中的解法索引仅作为快速导航，引导用户查看对应文件

### 3. 更新根目录 README 进度
```bash
# 统计题目数
ls -d src/*/ | wc -l
ls -d src/*/
```

更新 `README.md` 的"做题进度"部分：
- 更新已完成数量
- 按题号排序更新列表
- 补充新题目的难度和标签

### 4. 提交代码
```bash
git add "src/[题号].*/" README.md
git commit -m "添加/更新 [题号]. [题目名称] 题解并更新进度"
```

## 推送规则
- ❌ **不主动推送**：除非用户明确要求"推送"、"push"
- ✅ **可以本地提交**：执行 `git commit`

## 注意事项
- 不要覆盖用户解答
- 进度更新与题解总结在同一次 commit 中
- 只有用户要求"总结"时才更新进度
- **解答文件注释要精简**：函数上方注释控制在100字以内，评价犀利直击要害
- **评价关注算法思想**：不评价变量命名、代码风格等，只评价思路优劣
- **解法索引在 README**：不在解答文件中添加解法索引，统一在 README 中维护
- **多解法时分别标注**：每个解法文件都要有独立的精简总结和评价，并在 README 中汇总
